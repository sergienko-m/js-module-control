### Питання 1 — Тема: Змінні та типи даних
**Яке твердження про `const` є правильним?**

**Відповідь: B** — Змінну `const` не можна повторно присвоїти, але об'єкт за посиланням можна мутувати.

`const` забороняє повторне присвоєння змінної (`=`), але не забороняє зміну властивостей об'єкта або елементів масиву. Наприклад:
```js
const user = { name: "Іван" };
user.name = "Марія"; // ✅ можна — мутуємо об'єкт
user = {};           // ❌ помилка — перезапис посилання
```
Варіант A хибний — перезаписати не можна. Варіант C хибний — const не обмежено числами. Варіант D хибний — const має блокову область видимості, а не функціональну.

### Питання 2 — Тема: Змінні та типи даних
**Скільки існує примітивних типів даних у JavaScript?**

**Відповідь: C** — 7 примітивних типів.

У JavaScript існує рівно 7 примітивних типів:
1. `string` — рядки
2. `number` — числа (включно з Infinity та NaN)
3. `bigint` — великі цілі числа
4. `boolean` — true / false
5. `undefined` — змінна оголошена але не ініціалізована
6. `null` — навмисна відсутність значення
7. `symbol` — унікальний ідентифікатор

Всі інші типи (масиви, функції, об'єкти) є об'єктами, а не примітивами.

### Питання 3 — Тема: Умовні оператори
**Що поверне вираз `"" || "default"`?**

**Відповідь: B** — `"default"`

Оператор `||` повертає перше truthy значення або останнє значення якщо всі falsy. Порожній рядок `""` є falsy значенням у JavaScript, тому оператор переходить до правого операнда і повертає `"default"`. Якби рядок не був порожнім — наприклад `"привіт" || "default"` — повернулось би `"привіт"`.

Falsy значення в JS: `false`, `0`, `""`, `null`, `undefined`, `NaN`.

---

### Питання 4 — Тема: Умовні оператори
**Який результат матиме вираз `0 == false`?**

**Відповідь: A** — `true`

Оператор `==` (нестрога рівність) виконує приведення типів. `false` перетворюється на число `0`, і порівнюється `0 == 0`, що дає `true`. Саме тому рекомендують використовувати `===` (строга рівність), яка не виконує приведення типів. `0 === false` поверне `false`, бо типи різні (number vs boolean).

### Питання 5 — Тема: Цикли
**Який цикл найкраще підходить для перебору значень масиву без використання індексів?**

**Відповідь: B** — `for...of`

`for...of` перебирає значення ітерабельних об'єктів (масивів, рядків, Map, Set) без доступу до індексів:
```js
const arr = [10, 20, 30];
for (const value of arr) {
  console.log(value); // 10, 20, 30
}
```
`for...in` перебирає ключі (індекси) об'єкта, а не значення — тому не підходить для масивів. `while` і `do...while` потребують ручного управління індексом.

### Питання 6 — Тема: Цикли
**Що зробить оператор `continue` всередині циклу?**

**Відповідь: B** — Перейде до наступної ітерації, пропустивши решту коду в поточній.

`continue` не зупиняє цикл повністю (це робить `break`), а лише пропускає решту коду поточної ітерації і переходить до наступної. Наприклад:
```js
for (let i = 0; i < 5; i++) {
  if (i === 2) continue; // пропускає i=2
  console.log(i); // 0, 1, 3, 4
}
```

### Питання 7 — Тема: Функції
**Чим arrow function відрізняється від звичайної функції щодо `this`?**

**Відповідь: B** — Arrow function не має власного `this` і бере його з зовнішнього контексту.

Звичайна функція створює власний `this`, який залежить від того як функція викликається. Arrow function не має власного `this` — вона використовує `this` того scope де була оголошена (lexical this). Це особливо важливо в методах класів та callback'ах:
```js
class Timer {
  start() {
    setTimeout(() => {
      console.log(this); // this = Timer ✅ (arrow)
    }, 1000);
    setTimeout(function() {
      console.log(this); // this = undefined ❌ (звичайна)
    }, 1000);
  }
}
```

### Питання 8 — Тема: Функції
**Що означає синтаксис `function sum(...numbers)`?**

**Відповідь: B** — `numbers` збере всі передані аргументи у масив (rest parameters).

Оператор `...` перед параметром функції називається rest parameters і збирає всі аргументи що залишились у масив:
```js
function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4); // numbers = [1, 2, 3, 4] → 10
```
Не плутати з spread оператором `...arr` — він розпаковує масив, тоді як rest — збирає у масив.

### Питання 9 — Тема: Об'єкти
**Що повертає `Object.entries({ a: 1, b: 2 })`?**

**Відповідь: C** — `[["a", 1], ["b", 2]]`

`Object.entries()` повертає масив пар `[ключ, значення]` для кожної власної властивості об'єкта. Є три схожих методи:
```js
Object.keys({ a:1, b:2 })    // ["a", "b"]       — тільки ключі
Object.values({ a:1, b:2 })  // [1, 2]            — тільки значення
Object.entries({ a:1, b:2 }) // [["a",1],["b",2]] — пари
```
`Object.entries()` зручно використовувати для перебору об'єкта через `for...of`.

### Питання 10 — Тема: Об'єкти
**Як за допомогою spread-оператора об'єднати об'єкти `obj1` та `obj2`?**

**Відповідь: B** — `{ ...obj1, ...obj2 }`

Spread оператор `...` для об'єктів копіює всі власні властивості в новий об'єкт. Якщо обидва об'єкти мають однакові ключі — перемагає той що стоїть правіше:
```js
const obj1 = { a: 1, b: 2 };
const obj2 = { b: 3, c: 4 };
const merged = { ...obj1, ...obj2 };
// { a: 1, b: 3, c: 4 } — b від obj2 перемагає
```
`[...obj1, ...obj2]` — це spread для масивів, не об'єктів.

### Питання 11 — Тема: Події та DOM
**Що таке делегування подій?**

**Відповідь: B** — Встановлення одного обробника на батьківський елемент замість обробників на кожному дочірньому.

Делегування використовує механізм спливання подій (event bubbling) — коли подія на дочірньому елементі "спливає" до батьківського. Замість того щоб додавати обробник кожному `<li>`, додаємо один на `<ul>`:
```js
ul.addEventListener('click', (e) => {
  if (e.target.tagName === 'LI') {
    // обробляємо клік на будь-який li
  }
});
```
Переваги: менше пам'яті, працює для динамічно доданих елементів.

### Питання 12 — Тема: DOM
**Який метод створює новий DOM-елемент?**

**Відповідь: A** — `document.createElement()`

`document.createElement('div')` створює новий елемент у пам'яті. Щоб він з'явився на сторінці, потрібно додати його в DOM через `appendChild()` або `append()`. Інші методи: `querySelector()` — знаходить існуючий елемент; `appendChild()` — додає елемент; `newElement()` — такого методу не існує.

### Питання 13 — Тема: Масиви
**Що поверне `[1, 2, 3, 4].slice(1, 3)`?**

**Відповідь: B** — `[2, 3]`

`slice(start, end)` повертає копію частини масиву від індексу `start` до `end` (не включаючи `end`). Індексація з 0:
```js
[1, 2, 3, 4].slice(1, 3)
//  0  1  2  3
// від індексу 1 до 3 (не включно) → [2, 3]
```
`slice` не змінює оригінальний масив. На відміну від `splice` який змінює масив на місці.

### Питання 14 — Тема: Масиви
**Який метод видаляє останній елемент масиву і повертає його?**

**Відповідь: B** — `pop()`

```js
const arr = [1, 2, 3];
const last = arr.pop(); // last = 3, arr = [1, 2]
```
Порівняння методів:
- `pop()` — видаляє з кінця, повертає елемент
- `shift()` — видаляє з початку, повертає елемент
- `push()` — додає в кінець
- `unshift()` — додає на початок

### Питання 15 — Тема: Функції вищого порядку
**Що поверне `[1, 2, 3, 4].filter(n => n % 2 === 0)`?**

**Відповідь: B** — `[2, 4]`

`filter()` повертає новий масив з елементами для яких callback повернув `true`. `n % 2 === 0` перевіряє чи ділиться число на 2 без остачі (парне). Серед `[1, 2, 3, 4]` парними є `2` і `4`. Оригінальний масив не змінюється.

### Питання 16 — Тема: Функції вищого порядку
**Який метод зводить масив до одного значення?**

**Відповідь: C** — `reduce()`

`reduce(callback, initialValue)` проходить по масиву і накопичує результат:
```js
[1, 2, 3, 4].reduce((acc, n) => acc + n, 0)
// 0+1=1 → 1+2=3 → 3+3=6 → 6+4=10
```
`map()` — трансформує кожен елемент. `forEach()` — перебирає без повернення. `find()` — знаходить перший елемент за умовою.

### Питання 17 — Тема: Замикання
**Яке практичне застосування замикань (closures)?**

**Відповідь: B** — Створення приватних змінних та інкапсуляція стану.

Замикання дозволяє функції "запам'ятовувати" змінні зовнішнього scope навіть після його завершення. Це використовують для створення приватних змінних без класів:
```js
function createCounter() {
  let count = 0; // приватна — недоступна ззовні
  return {
    increment: () => ++count,
    get: () => count
  };
}
const c = createCounter();
c.count;     // undefined — приватне
c.get();     // 0 — через замикання
```

### Питання 18 — Тема: Проміси та async/await
**Що повертає функція, оголошена з ключовим словом `async`?**

**Відповідь: B** — Promise

Будь-яка `async` функція завжди повертає Promise, навіть якщо всередині немає `await` і просто повертається звичайне значення — воно автоматично обгортається в `Promise.resolve()`:
```js
async function greet() {
  return "Привіт";
}
greet(); // Promise { "Привіт" }
greet().then(console.log); // "Привіт"
```

### Питання 19 — Тема: Проміси та async/await
**Для чого використовується `Promise.all([...])`?**

**Відповідь: B** — Чекає завершення всіх промісів і повертає масив їхніх результатів.

`Promise.all` запускає всі проміси паралельно і чекає поки всі завершаться. Якщо хоча б один відхиляється — весь `Promise.all` відхиляється:
```js
const [users, posts] = await Promise.all([
  fetch('/users').then(r => r.json()),
  fetch('/posts').then(r => r.json()),
]);
// обидва запити йдуть паралельно
```
`Promise.race` — повертає результат першого завершеного. `Promise.allSettled` — чекає всіх, навіть якщо деякі впали.

### Питання 20 — Тема: Класи та ООП
**Що робить ключове слово `super` у конструкторі дочірнього класу?**

**Відповідь: B** — Викликає конструктор батьківського класу.

`super()` обов'язково потрібно викликати в конструкторі дочірнього класу перед використанням `this`, інакше буде помилка. Він передає аргументи батьківському конструктору:
```js
class Vehicle {
  constructor(brand) { this.brand = brand; }
}
class Car extends Vehicle {
  constructor(brand, doors) {
    super(brand); // викликає Vehicle constructor
    this.doors = doors;
  }
}
```
`super.method()` також використовується для виклику методів батьківського класу.
